# 📖 向量知识库 (RAG) 机制

Web3 的信息变化以秒计。为了让 AI 不仅有“常识”，更有“专业”，KiKo 引入了 RAG（检索增强生成）系统。

---

### 🧩 为什么需要 RAG？

大模型（如 Grok）的知识通常在训练完成那一刻就停止更新了。RAG 让 AI 具备了 **“翻书”** 的能力：

1.  **海量数据索引**：我们将最新的 DeFi 协议文档、API 更新日志等存储在 **ChromaDB** 向量数据库中。
2.  **语义检索**：当用户提问时，系统会将问题转化为向量，在数据库中寻找含义最接近的文档片段。
3.  **精准回答**：AI 会根据找到的真实背景，生成最新的、专业的技术解答。

---

### 🛠️ 知识库维护手册

如果你需要让 AI 掌握 KiKo 的私有逻辑或新的 API 规范：

*   **数据入库**：将新的 Markdown 或 PDF 文档放入 `kiko-python/rag/source` 文件夹。
*   **重新索引**：运行 `python manage.py reindex`，系统会自动完成分片 (Chunking) 与向量化。
*   **优先级调整**：可以在 Prompt 模板中设置，让 AI 优先信任 RAG 检索到的数据。

<callout> 💡 Tips: 一个高质量的 RAG 依赖于合理的 Chunking 策略。我们目前默认采用 800 字符重叠分片，以保留上下文的连贯性。 </callout>

---

### 🛡️ 边界与准确性

即使有 RAG，AI 依然可能在理解极端复杂的逻辑时产生偏差。
